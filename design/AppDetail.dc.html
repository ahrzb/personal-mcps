Board notes
• Seven panes behind one rail. App — Catalog (/apps/news, the landing), Roles, Recording, Overview; Access — Agents, Token; then the tail entry Danger zone. Each rail marker is the pane's own count: the catalog total, the effective role count (or none), a status dot for body logging, the agents holding a grant, the live tokens (a dimmed — for a proxied app). Overview, Danger zone and a proxied Token render the listing alone, wide.
• The header names the app once. The crumb is folded into the title line — Apps › News MCP, the ancestor small and the page big — then the slug, kind and status badges, the description as the subtitle, and one tiles line of totals. The kind badge stays (tunneled / proxied carries information); no separate “Last seen” note. A proxied app keeps its endpoint / auth / forward-identity card above the pane on every pane but Overview.
• Catalog folds the three families into one listing. Tools, Prompts and Resources as groups with their counts; an unadvertised family reads none advertised beside its heading with one note row beneath. A row is the name, its description, and one badge per agent that reaches it — claude for allow, claude · ask in amber — or the dim no agent. The row IS the ?sel= link; the filter matches name or description.
• Details answer “what would a call to this look like?” Arguments and Result are the schema's leaves as dotted paths (auth.api_key), not top-level fields, each with its type and a writeOnly · masked badge where the app declares one. What only the hub knows carries the four lines the audit row and the agent page show for the same endpoint: what it is called as on the aggregated endpoint, who reaches it and via what, what asks first, and what is redacted.
• Editing is where the thing edited lives. Reach on Agents, masking on Recording, definitions on Roles — the Catalog details link to both rather than duplicating a control. Granting a new agent is not started here: a note points at the agent's own page.
• Three forms, three ops. Roles posts one app_update { owner_roles | roles }, Recording one app_update { log_bodies, redact, redact_results }, Agents one grant_set — the same composer the agent page's route uses. Each pane's foot carries Discard and Save; every changed row wears the amber dashed unsaved badge and the rail entry a blue dot. Both are script-only, so the server-rendered page drops them, as the agent page did.
• Every column reads from ops that exist: app_get (catalog, roles, redaction), agent_list (grants), audit_query (calls per agent), token_list.
