Board notes
• Still one scroll, not panes: four sections (Access, Credentials, Activity, Danger) replace the three cards. The summary tiles are the row the list shows, unpacked.
• Access shows each app’s two lists exactly as the editor holds them (GrantEditorLists): Allowed and Needs approval, entries being roles or inline items, each chip carrying what it matches today. Under them, the same effective-access block the editor draws, collapsed to counts per §20 family and expandable to names with the entry that grants each. The “why it is less than you think” cases stay drawn: approval-only tools, a tools-only role on an app with resources, an archived app.
• Issue token gains the expires_in the op already takes (30 d / 90 d / 1 y / never); the once-only reveal is unchanged.
• Activity is approval_list filtered to this agent (Approve / Reject front approval_decide, the same as /approvals) plus audit_query { principal }: five rows and a link, no second audit page.
• Connected clients grow “consented” and “used” from connection_list’s own columns; Revoke still lives in Settings (§19.6: one place revokes).
