Board notes — listing + details
• The grant set has no pane of its own. It is read off the listing: a role row says "in Allowed" or "in Needs approval" with an × to remove; an item row says how it is reached and, when there is a direct entry, "direct ×". A separate Patterns group at the end holds the entries that are not one item, so nothing stored is invisible.
• Adding is Allow / Approval on a row (hover), or typing a pattern into the filter, which offers it as a row with its match count. Removing is the ×. The unsaved bar sits at the foot of the listing; Save posts the whole set as grant_set.
• The details pane is the app page's expanded tool row (description, arguments, the four hub lines) plus a "For claude" block: standing, whether approval would even apply, recent calls by this agent to this tool, and the two actions again. The URL carries the selection (/agents/claude/apps/news/tools/search_items) so a row is linkable and scripting-off works by reload.
• Nothing selected: the details pane shows the app's summary — kind, status, catalog counts, roles, body logging — so the pane is never blank.
• Reads: the catalog and roles the reach needs, plus audit_query { principal, app, tool } for the selected item only. Everything else is already on the page.
• Width: 180 + 520 + the rest at 1240. Narrow: rail becomes the pill row; details opens as its own screen from a row tap, back returns to the listing.
