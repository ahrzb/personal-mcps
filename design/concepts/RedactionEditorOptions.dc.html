Common to every option
• Where the schema comes from: a tunneled app's cached catalog, a proxied app's live listing — the reads the Tools pane already does. No new op.
• Nested and array fields are walked the way the writeOnly walk walks them (refs resolved, unions merged); an array's items appear once and the path applies to every element, as the masker does.
• Results are offered only where the tool declares an output schema. Without one, the only way to name a result path is from a recorded body (mask from evidence), and the option says so in place rather than offering a text box.
• Patterns (search_.* as the key) are not produced by any of these; they stay a CLI / provider spelling and appear in the stored list as their own row. Ticking across tools writes literal entries, one per tool.
• One save: whichever option, the result is the same app_update { redact, redact_results } the pane posts today.
