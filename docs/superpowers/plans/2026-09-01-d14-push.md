## Implementation constraints (verifier-derived; violating any one makes oracle rows unassertable or vacuous)

1. **`tunnel.ts`'s `socket()` reader becomes tag-aware.** Today it is
   `const [ws] = this.ctx.getWebSockets()` — position, not class. Five paths read
   through it (`live`, `status`, `sever`, `alarm`, `evictCurrent`); with a subscriber
   socket accepted first, every one selects the wrong socket (offline reads online, a
   token revoke no-ops, `hub/replaced` evicts a consumer). The reader selects the socket
   tagged with the bare service id. This is the single highest-value change in the
   dispatch.
2. **One alarm slot, multiplexed.** The registration deadline and the bell coalescer
   share the DO's alarm: purpose is stored state, the handler dispatches on it, a socket
   accept cancels no pending ring, a subscriber accept never arms the deadline, and the
   coalescing leg **fires the pending ring unconditionally when it runs** (no clock
   re-check — that is what makes `runDurableObjectAlarm` a usable oracle lever).
3. **The keepalive is a bare `setTimeout(…, LISTEN_KEEPALIVE_MS)`** so the suite's
   exact-match constant-shrink shim reaches it (the repo's only timing lever; an
   interval, `scheduler.wait`, or an alarm would strand every tick-dependent row at
   real-time). The shim maps exact constants, never `ms >= X`.
4. **The pure seams live in a Node-clean module** (no `cloudflare:workers` in the
   transitive import graph — `gateway.ts` drags it in via `admin.ts`, verified
   empirically): comparator, capability shape, tag builder/parser, `admits()`, family→
   bell map go in `server/src/capabilities.ts` (or `registry.ts`); `gateway.ts`
   re-exports. The capability shape takes a **three-member kind**
   (`"tunnel" | "proxy" | "builtin"`).
5. **Floor state is durable**: per-family last-rang timestamps and the pending-ring flag
   live in DO storage, not instance memory — they are the fifth tier of
   `hibernation.test.ts`'s survival table.
6. **The ring path enumerates subscriber sockets by tag** (`sub:` prefix over
   `getWebSockets()`), never an in-memory list — it must still ring after an eviction.
7. **Two named exports for the contracts producers**: the hub→service forwarded-method
   set in `gateway.ts` (beside the dispatch switch), and the service-originated
   notification frames the DO reads in `tunnel.ts` — a value that distinguishes
   "invalidates family X" (the three `list_changed`) from "routes by `uri`"
   (`resources/updated`), since the existing `LIST_CHANGED` record cannot hold the
   fourth frame without lying about it.
8. **Subscriber sockets are opened through `ServiceConnection.fetch()`** — a second
   upgrade door beside `/connect`'s. The test harness opens them the same way
   (`stub.fetch(upgrade)`, peer accepted test-side): a socket fabricated inside
   `runInDurableObject` silently vanishes at `evictDurableObject` (measured), which
   would make every hibernation row vacuous.
9. **`-32602` lands in `errors.ts`'s consumer vocabulary** (its comment currently
   classes it owner-config-only) and in `contracts/errors.json`; the totality row
   becomes six codes.
10. **Suite discipline:** every "rings nothing" row concludes only after firing the
    coalescing alarm (`runDurableObjectAlarm`) — "never rang" and "suppressed" are
    otherwise indistinguishable. Existing rows that pin the pre-flip world are
    **deleted-and-replaced, never left red**: `order.table.test.ts` :1993/:2002/:2020/
    :2045 and `contracts.test.ts` :1252/:1286. `order.table.test.ts:2075`
    (initialize ≡ discover) is flip-agnostic and needs no edit.

session scratchpad).

**Judged:** the PSD question above, plus one adversarial read of §21.4 against the

whose principal never passed the subscribe filter for that URI?
