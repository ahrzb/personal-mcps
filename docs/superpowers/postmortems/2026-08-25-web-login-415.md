# Web login rejects the browser's form post with 415

- **Found:** 2026-08-25, by the user, signing in at `/login` on production for the first time
- **Symptom:** `{"message":"Content-Type \"application/x-www-form-urlencoded\" is not allowed. Allowed types: application/json","code":"UNSUPPORTED_MEDIA_TYPE"}` immediately on submitting the login form
- **Impact:** web sign-in entirely broken in production from the moment the pages shipped until the fix deployed; every credential form (login, and the sibling better-auth forms) affected; CLI/device flow unaffected
- **Class:** boundary-actor, exclusion-intersection

## Root cause

The server-rendered templates submit as native HTML forms —
`application/x-www-form-urlencoded` — directly to better-auth's endpoints,
which accept only JSON. No translation layer existed between the browser's
encoding and the third-party mount's contract. The two sides were each tested
against their own contract and never against each other.

## Why the tests missed it

Two individually principled exclusions intersected on exactly this form:

1. The CSRF walk excluded `/login` — "no session exists yet to derive a token
   from", true and sufficient reason not to check CSRF there, silently also
   meaning the walk never *submitted* the form.
2. The §8 parity walk excluded better-auth-mounted forms — the credentials
   exception (auth family never exposed to models/tests as a surface), again
   principled, again silently removing the submission.

Every rendered form was walked by at least one suite — except the intersection.
Nothing enumerated the exclusions and checked they summed to zero unwalked
controls.

## Fix

Translation routes in `server/src/web.ts` (form-encoded in → `identity.callAuth`
JSON → Set-Cookie forwarded back), `paths.auth.*` repointed in
`server/src/pages/model.ts`, plus form-encoded oracle test cases submitting the
forms exactly as a browser does. Landed 2026-08-26, commit `c6abf9d`
(gated: suite 904/904, tsc 0, pytest green, live-proven). The fix turned out
three-headed — sign-out 415'd on its empty form post, and better-auth's
MISSING_OR_NULL_ORIGIN rule refused every cookie-bearing internal call, so
/device approve/deny was broken too; all one root cause, fixed at the seam.

## Candidate countermeasures (recorded, not enacted)

- **Enacted same day** (pre-dates this track): testing-strategy §9 rule 4 —
  (a) every walk's exclusions are enumerated and *spent* against a totality
  case over all rendered controls; (b) every rendered form is submitted exactly
  as a browser would submit it, third-party mounts included.
- Generalization (not enacted): every surface names its real actor
  (browser / CLI process / runtime) and gets at least one case driven through
  that actor's actual mechanics rather than an in-process shortcut.

## Misdiagnoses along the way

None — the error message named the mismatch directly.
